A · hsm/ bugs

Bugs in the docking / pose-selection pipeline. Sources: manual review of hsm/src/.

#1Criticalhsm/src/indiv/extract_bsites.py:33TypeError — get_ligand() return value treated as a single dict

Problem get_ligand() returns a list of residue dicts, but the caller indexes it as a single dict: if len(lig["atoms"]) == 0 → TypeError: list indices must be integers, not str.

Fix Check if len(lig) == 0 (empty list), then use lig[0] (or iterate) when calling get_bsite.

#2Criticalhsm/src/autodock/get_poses.py:21ValueError on non-ATOM last line of PDBQT file

Problem maxn = int(site[-1][ATNO]) — PDBQT files end with END. site[-1][6:11] on a 4-char string gives "", and int("") raises ValueError.

Fix Filter site to ATOM/HETATM lines first and take the last of those.

#3Highhsm/src/rotate.py:22,35Missing comma merges two subprocess.run list elements

Problem [..., "-O" f"{IN}/{TEMPLATE}_HSM.mol2"] — the missing comma causes Python to string-concatenate into a single element "-O/path/file" instead of two separate "-O", "/path/file". Same on line 35.

Fix Add the missing comma: "-O", f"{IN}/...".

#4Highhsm/src/autodock/clusternums.py:32Bare raise outside except block

Problem The else clause of the inner for loop (runs when the closing histogram separator is never found) contains a bare raise with no active exception → RuntimeError: No active exception to re-raise.

Fix Replace with raise RuntimeError("histogram separator not found") or similar.

#5Lowhsm/src/autodock/main.py:171Unreachable error-handling block after check=True

Problem subprocess.run(..., check=True) raises CalledProcessError on failure before control reaches the if result.returncode != 0 block on line 171 — that branch is dead code. The except CalledProcessError below handles it but doesn't re-raise RuntimeError as the dead branch intended.

Fix Remove the dead if block; raise RuntimeError from the except handler if callers depend on it.

#7Criticalhsm/src/Motif.py:13,29,208,231Python 2 print statements cause SyntaxError

Problem Multiple bare print statements without parentheses (lines 13, 29, 208, 231) are a SyntaxError in Python 3. The rest of the codebase is Python 3, so this file cannot be imported or run.

Fix Add parentheses: print(...).

#8Highfilt/src/res.py:32UnboundLocalError when no REMARK pattern matches

Problem If a PDB file has neither a REMARK 2 RESOLUTION line nor a REMARK 3/4/5 terminator, the loop exhausts without assigning res or raising ValueError. return res then raises UnboundLocalError. The caller in choose_reprs.py catches ValueError but not UnboundLocalError, so it crashes unhandled. See also #18.

Fix Add a for/else clause: else: raise ValueError(f"Resolution not found for {pdb} (1)") — already present in methods.py:get_res.

#9Highhsm/src/autodock/collatereports.py:14'PDB' in l silently corrupts output on any line containing "PDB"

Problem if 'PDB' in l is intended to match only the single header line naming the structure, but matches any line whose content contains the substring "PDB" (e.g. residue/atom names). When such a line appears mid-parse, out[pdb] = {} wipes all collected interaction data and replaces pdb with a garbage slice l[62:-14]. Subsequent rows are written under the wrong key with no error or warning.

Fix Match the exact PLIP header line format (e.g. a regex anchored to the known prefix) rather than a bare substring.

1 · Bugs that diminish or corrupt the curated output

These directly change which binding sites end up in the final dataset.

#11Highres.py:12-19Cryo-EM structures treated as having no resolution

Problem get_res reads only REMARK 2. For EM structures, REMARK 2 says RESOLUTION. NOT APPLICABLE. (no match), then the REMARK\s{3}[3-5] sentinel fires on the first REMARK 3 and raises ValueError — but the real EM resolution lives in REMARK 3.

Impact In a mixed cluster an X-ray site always beats EM regardless of quality; in an all-EM cluster resl is empty → falls back to cluster[0] (arbitrary file order). Histamine receptors are largely cryo-EM, so this is scientifically significant. (Mechanism inferred from regex + record ordering; could not byte-verify without reading .ent files.)

Fix When REMARK 2 is NOT APPLICABLE, parse REMARK 3 RESOLUTION RANGE HIGH (ANGSTROMS) : instead of treating REMARK 3 as a terminator.

2 · Dangerous / destructive operations

#16Highmove_reprs.sh:4find … -delete empties the reprs dir at startup

Problem Deletes every file in representative-binding-sites/ before the copy loop, with no existence/backup check. An empty or wrong cluster_reprs.txt leaves nothing copied back. (Also no mkdir of the target → cp fails per line if it doesn't exist.)

Fix Verify the dir + input first; make idempotent or back up before the blanket delete.

4 · Diagnostic scripts that don't do what they claim

These don't build reprs.json, but you use them to validate it — wrong logic here gives false confidence.

#23Criticalf_missing.py:121,134 · f_missing2.py:96,108Entity-vs-cluster comparison can never match (ID-format mismatch)

Problem enties holds XABY_N strings, but clusters is sliced to bare enty[:4] (XABY). So ent not in clusters flags every entity.

Impact "number of unaccounted-for entities not in the clusterfile" is inflated to the full count — a wrong diagnostic, present in both files.

Fix Compare full entity IDs on both sides (don't slice to [:4]).

#28Lowstats.py:15Fixed-offset ligand slice corrupts non-standard names

#32Lowmissing_bsites.py:42 · getentities.sh:38 · removed.sh:13PDB-list file referred to inconsistently as pdb.txt vs pdbs.txt

Problem The list-of-all-PDBs file is opened as pdb.txt in missing_bsites.py:42-46, getentities.sh:38 and removed.sh:13, but is named pdbs.txt in some environments (the canonical name differs between the dev and main machines). Whichever spelling a script hard-codes may not exist on a given machine → FileNotFoundError (Python) or a silently-empty grep (shell). missing_bsites.py was previously pdbs.txt and was changed to pdb.txt to match the shell scripts, which aligns the code but not necessarily the on-disk file.

Fix Pick one canonical name, rename the data file and every reference to match across both machines (or symlink one to the other). Don't rely on a single machine's filesystem to decide which is correct.

~ · Contingent — won't arise with a clean pipeline

These bugs only trigger when a prior step produced malformed or missing output. Fix the upstream step first; revisit these if malformed inputs are a real concern.

#18ContingentHighchoose_reprs.py:42-46Only ValueError is caught around get_res

Problem get_res can also raise FileNotFoundError (missing .ent) and UnboundLocalError (res.py returns res unbound when neither REMARK pattern matches). Neither is a ValueError.

Impact A single odd/missing structure aborts the entire representative-selection stage and no reprs.json is written.

Fix Catch (ValueError, FileNotFoundError) here; initialize res = None (and raise ValueError) in res.py.

#20ContingentMediumclusterize.py:126,130-137l[-1]/l2[-1] on an empty CHAIN payload → uncaught IndexError

Problem A blank/short CHAIN: line makes line[18:].strip() empty, and l[-1] raises IndexError — same escape path as above (not caught by clusterize()). Standard formatting won't trigger it, hence Medium.

Fix Guard for empty l/l2 before indexing; consider catching IndexError.

#24ContingentHighf_missing2.py:61, 96NameError on chains, and zip(*enty_names) on empty input

Problem print("FAILED - ", bsite, chains) references chains, only bound inside the CHAIN: branch → NameError if SOURCE comes first (f_missing.py:80 is safe). Separately, enties, _, names = map(list, zip(*enty_names)) raises ValueError when enty_names is empty (both files).

Fix Drop chains from the print; guard if enty_names: before unpacking.

#25ContingentHighlig.py:62rn can be unbound → NameError

Problem rn is only assigned inside the HETATM branch; the for…else prints it when a structure has no HETATM before EOF → NameError aborts the whole copy run.

Fix Drop rn from the print, or initialize rn=None before the loop.

#27ContingentMediumlig.py:44 · missing.py:21Unguarded int(rn) on the HETATM residue-sequence field

Problem rn = l[22:26] is fed to int(); a non-numeric resseq (overflow **** or blank in a malformed record) raises ValueError and aborts.

Fix Wrap in try/except, or compare the resseq as a stripped string.

✓ · Completed

These bugs have been verified fixed.

#19FixedMediumclusterize.py:103,116ENTY_PATTERN = [… range(166)] indexed by entity number

Problem Max entity is 165 today, so it works — but the pipeline re-runs on PDB growth. The first XXXX_166 makes ENTY_PATTERN[166] raise IndexError, which is not in the except (FileNotFoundError, ValueError) → the whole run crashes rather than skipping one entry.

Fix Compile the regex per-call (re.compile(rf"…MOL_ID:\s*{enty};")), size the list from the data, or add IndexError to the caught tuple.

#14FixedMediumfilterbsites.sh:95Unquoted $lig in the grep test

Problem If a filename is malformed and token3 is empty, grep -qw "" matches every line, so the site is always classified unwanted. Whitespace would word-split into extra args. (Also affects remove_unwanted.sh:27.)

Fix Quote it — grep -qw "$lig" — and skip files whose token3 is empty.

#13FixedHighfilterbsites.sh:92Residue-count dedup is non-deterministic

Problem awk substr($0,22,5) | sort -n | uniq | wc -l: the key is a chain+resnum string (e.g. A 21), so sort -n's numeric key is 0 for every line; correct grouping then relies on GNU sort's undocumented whole-line tiebreak. Under sort -s or some locales, duplicates aren't adjacent and survive uniq, inflating the count.

Impact Under-4-residue sites can pass the "≥4 amino acids" filter. (Minor: substr($0,22,5) omits the col-27 insertion code, collapsing iCode-only-distinct residues.)

Fix Use sort -u (lexical) instead of sort -n | uniq.

#12FixedHighfilterbsites.sh:95Unwanted-ligand filter silently disabled if the list isn't found

Problem ! grep -qw $lig unwanted-ligs.txt — if the file is absent, grep exits 2 and ! grep is true, so every site passes the ligand check. The path is relative while the rest of the script uses absolute bsites_base/out_base, so a different CWD triggers exactly this.

Impact Unwanted ligands (HOH, SO4, metals, buffer) leak into the curated set with no error.

Fix Use an absolute, existence-checked path; quote "$lig".

#10FixedCriticalclusterize.py:53Last entity per line dropped when its entity number is ≥100

Problem [enty.strip() for enty in clust.split(" ") if len(enty) <= 8] checks length before .strip(), so the final token still carries \n. 8GZU_139\n is length 9 → discarded; 8GZU_139 would be 8 → kept. Confirmed exactly 105 such entries in clusters-by-entity-70.txt.

Impact Those entities' binding sites never enter any cluster → lost entirely (singleton clusters) or excluded from representative selection (multi-member clusters). Replicated in f_missing.py:130, f_missing2.py:104, missing_bsites.py:58.

Fix Use clust.split() (no-arg split strips whitespace + handles multi-space/empty tokens), or if len(enty.strip()) <= 8.

#15FixedCriticalsortbsites.sh:45-46Unconditional shutdown when the file count hits 0

Problem When the top-level file count reaches 0 — the success condition, or if the dir is empty/missing/mistyped — the script runs bare shutdown: ungated, no confirmation. By contrast extractzip.sh:15 / rsyncPDB.sh:111 correctly gate behind [[ $1 == "sd" ]].

Impact Powers off the machine mid-pipeline (subject to privileges).

Fix Gate it the same way ([[ $1 == "sd" ]] && shutdown), or delete the call.

#21FixedCriticalextractents.py:10,20,55Stuck in debug mode — scans one dir, writes nothing

Problem debug="1pv0" is truthy, so if not debug or d == debug[1:3] reduces to d == "pv" (only pdb/pv/ is scanned), and if not debug: is False so ents2.txt/failedents.txt are never written.

Impact The entity-ID list is never generated; downstream consumers get no input.

Fix Set debug=None (or "").

#22FixedCriticalmissing_entys.py:32Existence check builds a path that can never exist → vacuous "confirmation"

Problem pdb is an UPPERCASE 4-char id; f"{INDIR}/{pdb[1:3]}/{pdb}" → …/pdb/G2/1G29 (wrong-case shard, no pdb prefix, no .ent). os.path.exists always fails, so every pdb is added to missing_pdbs.

Impact The printed "confirmation that all missing entities come from missing pdbs" is vacuously true — the claim is never actually tested.

Fix f"{INDIR}/{pdb[1:3].lower()}/pdb{pdb.lower()}.ent".
